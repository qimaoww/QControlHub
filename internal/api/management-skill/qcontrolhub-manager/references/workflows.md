# Management operations

Search with `python3 scripts/operations.py list TERM`. Paths below are relative to the API base. For JSON requests use `python3 scripts/qch.py METHOD "/concrete/path" --body-file "$BODY"` with a private file containing the reviewed fields. Omit the body option for requests without one. URL-encode each substituted path segment and each query value separately.

## Nodes, users and sharing

- Find accessible nodes through `/agents` or `/agent-directory`. Read the current node before changing its name, visibility, region, time zone, client address or engine capabilities. Use `/regions` for valid region choices and `/region-flags/{code}` for the flag. After saving, re-read the node or its corresponding setting. Before deleting a node, establish the impact on its instances and shares.
- Use `/agents/{id}/sharing` for the node owner's shares, `/agent-access` for the current user's invitations and `/agent-access/{id}/response` to respond. For another user's node allocation, inspect `/users/{id}/agent-access` before saving it. Keep the share ID, owner and engine attached to the selected instance. Diagnostic grants are separate under `/agents/{id}/diagnostic-grants`.
- Look up the account in `/users` before editing it. Confirm the resulting account state after a permitted change. A Key cannot increase account permissions or re-enable an account. Account creation, deletion and purge, Key administration, enrollment commands and tokens, login and certificate-account credential management have separate authentication requirements. Report the catalog's boundary when the request needs one of these.

## Configuration, services and deployments

- Select the agent and engine, then read its `configs/{engine}/workspace`, configuration and state. The workspace snapshot and `/config-catalogs/{engine}` describe the selected configuration and engine. Choose the specific API for files, managed options, fields, inbound or outbound entries, generated plans or full source. Read the current entry before editing. Bind the saved version and allocated instance wherever required. Use the workspace `client-access` operation for the requested inbound or WireGuard client export.
- For standalone archives, list `/configs`, create or update the selected archive, then read `/configs/{id}/revisions`. To restore, inspect the selected historical version before submitting its restore operation and check the new saved revision. Applying `/templates/{id}/apply` saves a configuration for the selected node. Verify the saved configuration before any separately authorized deployment.
- For configuration-bound validation or deployment, use `POST /configs/{id}/tasks` with the actual configuration version and instance. For node service operations use `POST /tasks` and inspect its request schema and action restrictions. This covers start, stop, restart, status, install, uninstall, configuration reads and Agent upgrades. Use dedicated proxy, import, diagnostic and TLS operations when their action requires a plan, snapshot or session. Read the TCP parameters and latest TCP tasks before requesting a host-wide BBR or TCP change.
- To import existing configuration, identify the node owner's completed read task and its snapshot. Submit to the engine's `/import` with the current version, then check the import task and resulting revision. For access-control changes, read `/access-controls`, bind the correct inbound and version, and check the saved policy and task for the selected intent.
- Use `GET /tasks/{id}?view=status` for task state. Cancel an eligible pending task. For a failed task, inspect retry and edit-and-retry eligibility. Inspect its diagnostics or config snapshot only within the requested scope. Fetch its retry editor before an edited retry. Follow the returned attempt ID, then check `/deployments` and the node's actual state for deployment work. The `/tasks/failures` route records a panel failure.

## Certificates, client access and subscriptions

- List `/certificates` and read the selected certificate. For issuance, first identify the permitted account or HTTP validation node. For replacement, renewal, automatic renewal and deletion, check existing bindings. Use the certificate's grants for sharing and `/certificate-http-grants` for HTTP validation authority. Continue or cancel an order by its certificate and order IDs. Verify certificate status, version and affected bindings after the operation. Use `public-chain` for the public chain.
- Look up managed sources before changing synchronization for a source. Account listing and account credential management have different authentication. Select by stable identifiers when domains or names coincide.
- Use `/client-access` for authorized deployed profiles and the scoped workspace export for a specific configuration. Exports may contain client credentials. Confirm the requested client, format and private delivery destination before retrieving them.
- Read `/substore-sync` for current settings, targets and selections. Test the configured connection before remote discovery, linking or import. Save selections for the chosen target, then use `/substore-sync/run` only when a remote sync is requested. Verify that target's sync result. Editing selections or testing connectivity alone does not publish them.

## Traffic, connections and diagnostics

- Query `/traffic-usage`, `/traffic-endpoints` and `/traffic-policies` for the selected node, period and policy. Endpoint sync has separate GET preview and POST execution. Both require the catalog's stated Key mode. For quota edits, resets, monitoring removal or policy deletion, identify each policy and inspect the resulting policies and usage. For batch management use the requested IDs and request ID, and inspect each member's status including failed and unexecuted rows.
- For connection history, retain the filters and returned cursor across pages. For core logs, use `/core-log-sources` and `/core-logs` with the actual agent, engine and instance (`main` or the assigned share ID). For older rows, pass the smallest returned log ID as `before`. Scope access to private connection and log data to the requested investigation.
- For network diagnostics, resolve the eligible endpoints through `/network-diagnostics/nodes`. Submit the authorized session once and query `/network-diagnostics/{id}` for its state. Use its stop operation if requested. Cleanup may still be pending after a stop. For an IP quality check, follow the returned task, read `/ip-quality` with the intended date and timezone and select the matching address family for an archive. Read back schedule changes in IP quality history.

## Panel, monitoring and personal preferences

- Use `/overview`, `/panel-metrics` or `/metrics/{id}` according to whether the user needs the workspace overview, panel metrics or a node's samples. Scope `/audit` to the investigation and inspect only the requested range. Software update checks and deployment information are under `/settings`.
- Read current settings or branding before saving. For notifications, inspect the channel and revision, preview the requested event, and send a test only when authorized to contact that channel. Check the delivery history afterwards. Keep existing credentials when the documented request permits it.
- Personal settings live under `/preferences` and include theme, node order and view, traffic order, per-page size and UI choices. Read the current user's value and revision, change the intended fields, then fetch the same preference under the same identity to verify it.

## Reading results

The helper prints a limited projection of JSON responses. An empty object can also mean that the payload was filtered or that the operation returns a file. Do not interpret it as an empty resource, a downloaded artifact or proof that a setting took effect. Use the authorized follow-up query and report missing evidence. To save a requested Skill ZIP, flag, IP quality SVG, public chain or workspace client export, add `--download "$NEW_FILE"` to its GET. Use a new path in the agreed private directory. The helper prints only the byte count.
