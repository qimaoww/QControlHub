# 端口流量统计

## 统计口径与存储

双链路统计按代理入口归属四个方向：客户端→代理、代理→客户端、目标→代理、代理→目标。接收为前者与目标回包之和，发送为客户端回包与出口请求之和。因此常规转发的接收/发送累计通常接近，但协议握手、加密封装、重传、拦截和缓冲会产生真实差额，绝不强行配平或乘二。

- Xray：独立出站 tag 与只读 Stats API，读取各入站及所属出站计数；入站可能包含代理协议握手开销。
- sing-box：具有 `with_v2ray_api` 的构建使用原生 API；没有该功能的官方构建自动使用独立出站 `routing_mark` 与 nftables/conntrack。
- Mihomo、SS Rust：独立出口标记与 nftables/conntrack，不通过轮询活跃连接列表推算已结束连接。统计包含网络层包头、加密开销和重传。Mihomo 不标记回环等非全局单播目标，这类目标的出口链路不在完整归属范围内。
- 未迁移或复杂配置无法安全建立独立出口时，保留原监听端口统计并显示原因，不宣称双链路可用。已启用双链路后遇到采集错误时保留旧基线，不替换成另一种口径的字节数。
- 仅 TCP / 仅 UDP 策略在托管配置可验证该端口独占相同入口协议时使用双链路统计，包括纯 UDP 入站。混合协议、未知传输或重复端口仍退回 `listener-only`，不将共享统计混入单协议配额。出口可使用不同于入口的协议，标记出口始终累计 TCP 和 UDP。来源故障保留已有原生基线，恢复后不重复计费；口径变更保留已用配额，不重算历史。

Xray 自定义 API tag（例如 `api`）按 API 声明及专用入站路由识别，不再视为普通出口。已有 API 服务保留并补充 StatsService，增加固定回环统计监听。专用 API 入站不参与业务端口自动发现；必须监听回环地址，非标准直接 API 监听地址仍需安全核验。代理访问内部 API 端口会被拦截，专用内部 API 路由保留。既有自动发现记录按控制面的常规同步规则清理，显式配额记录不自动删除。

监听端口计数覆盖节点 INPUT / OUTPUT 的 IPv4、IPv6、TCP、UDP，不统计纯 FORWARD / Docker bridge 转发路径。标记计数要求连接经过 conntrack；自定义 NOTRACK、策略路由、共享传输、跨网络命名空间等配置必须单独核验。不同计数层级不等价，不承诺与云厂商账单一致，也不能把所有端口之和直接解释为物理网卡总量。

额度为接收加发送，输入单位为 GiB（1 GiB = 1,073,741,824 字节）；速率为 B/s。配额以 UTC 日历月/年为周期。页面累计值属于各端口当前周期；历史页来自数据库每日汇总。

- PostgreSQL `port_traffic_policies` 保存当前周期用量、收发速率、周期、封禁/可用性、实际采样时间、计量代次、周期原始基线和跨周期 lifetime 原始基线。
- PostgreSQL `port_traffic_daily_usage` 保存每日收发、合计、峰值速率、样本数及端口元数据快照。基线更新与每日增量在同一事务内提交，任一端口写入失败整批回滚。
- schema 44 的 `port_traffic_policies.accounting` 保存统计来源、入站/出站映射、出口标记、进程代次、四方向累计和原始计数器；`port_traffic_accounting_epochs` 按计量代次保留这些恢复信息。`port_traffic_daily_accounting` 从升级后开始按来源分别保存每日收发增量，避免把新旧来源当成同一种计量。
- schema 45 为历史归属独立保存节点 ID，删除端口或移除配额不再级联删除历史；明确删除节点或清除监控历史时仍会清理。恢复旧计量代次时读取该代次的数据库基线，只累计尚未确认的增量；监听端口统计也保存代次基线。升级前已经被删除的历史无法自动恢复。
- Agent 的私有 `traffic-state.json` 是断线期间的本地恢复检查点，不是控制面的唯一数据源。它保留每个 TCP/UDP、收/发计数器的值和内核对象身份，以及宿主机启动标识；有变化的采样在发布成功快照前以临时文件、fsync、原子重命名持久化。正常退出会等待最后一次采集与检查点完成。

## 准确性保障

计量采用 nftables [命名计数器](https://wiki.nftables.org/wiki-nftables/index.php/Counters)。刷新、封禁和解封只在一个事务中替换规则，保留仍在使用的计数器对象；读取计数后到规则提交前到达的字节会在下一次采样收回。不重复安装未改变的策略。旧匿名规则在升级时采集一次已有增量，再迁移到命名计数器。

每个方向/协议独立计算增量，避免一个 TCP 计数器归零被 UDP 增长掩盖。对象 handle 改变或宿主机重启时重建内核基线，而保留本地累计量。封禁规则在计数语句之前丢包，拒绝的尝试不进入用量；最终一次允许通过的增量仍会计入。规则事务失败不会提前宣称封禁成功，并在后续采集重试。

上报携带实际采样时间和计量代次。重复/乱序样本不重复入账；网络抖动或心跳与轻量指标重复携带同一快照，不会人为制造短间隔速率尖峰。采集失败不推进数据库计数基线，也不增加日样本数；UI 对异常、离线或过期的采样显示零速率。

原生 API 在同一进程内缺失已有非零基线的计数器时，整次端口采样视为不完整，保留四方向旧基线并报告异常。恢复后只累计新增量，不能将缺项当作归零后重复累计历史；首次尚未使用的惰性计数器和经确认的进程重启仍允许缺项。

nftables 响应中的字节字段必须存在且在支持的整数范围内；缺失、null 或重复命名计数器均作为采集失败处理，不将其默认为零污染累计基线。明确返回的零值仍允许用于新建或重置的计数器。

不随日历清零的 lifetime 基线使跨周期前未发到控制面的尾部流量仍能进入历史；新周期配额仅使用新周期用量。所有合计使用有符号 64 位上限饱和运算，避免两个合法方向相加溢出导致整批被拒绝。

本地计量状态丢失后，Agent 会利用控制面已确认的当前周期用量作为配额恢复基线，继续执行剩余额度；这部分不会作为新流量再次上报入账。下一个日历周期会清除该恢复基线。

## 精度边界

- 默认约每秒采集；跨周期边界的一个采样间隔归入新周期，自动封禁也存在采样和规则提交延迟，不能当作逐包硬限额。
- 每日历史按采样结束的 UTC 日期归集增量，不是逐包时间账本。长时间离线期间的总量可以补回，但无法从两个累计值恢复离线期间逐日的真实分布；也不以补报流量制造实时峰值。
- 本机规则计量发生在专用 hook 位置，不能证明随后一定成功交付应用或客户端，也不排除后续其他防火墙链丢包。
- 突然断电仍可能丢失最后一次成功检查点之后、尚未采集的内核增量。若同时丢失本地检查点和内核对象，已入数据库的历史保留，但未上报的数据无法凭空恢复。
- 从旧匿名计数器迁移有一次旧规则读取到事务提交的短窗口；后续普通规则刷新不再存在这种清空损失。

## 升级与验证

先升级控制面（自动迁移至 schema 45），再升级 Agent；旧 Agent 可继续向新控制面上报。新增字段/表不清零历史。Agent 启动时只迁移已验证且正在运行的 QAgent 托管服务，跳过等待导入的系统服务；迁移先校验、备份，再重启对应内核，重启失败自动恢复旧配置并尝试恢复服务。选择标记计量的内核服务需要 CAP_NET_ADMIN；Xray 原生 API 路径不新增此权限。无法安全处理的自定义路由、共享/复用出站、已有自定义标记或 API 会保留原配置并明确报告。

切换统计来源会新建计量代次并建立基线，不重复计入该内核此前已累计的流量。历史不会被重新解释为双链路字节数；当前配额会保留切换前的已用基线。内核重启通过进程启动标识识别，各出站计数器独立求增量。

采集失败时整次采样的基线均不推进，标记统计恢复后会补回客户端与目标两条链路。关闭自动封禁、提高额度到已用量之上或进入新周期不依赖统计 API 恢复；这些操作仍会解除旧封禁，未上报计数保留到采集恢复后入账。

回滚控制面前需恢复升级前的数据库备份，旧二进制会拒绝较新的 schema；不要手工降低迁移版本号冒充回滚。

## 配置文件

预设页保存入站前检查整份配置的独立出口规划，编译后的专属出站、入站路由和出口标记随配置版本一起加密存入 PostgreSQL，而不只留在 Agent 磁盘。无法建立安全归属时拒绝保存，不提交部署任务；可在手动配置页处理复杂自定义配置。修改已编译预设时先验证并移除旧自动副本，再按新增、修改或删除后的端口重新生成；SS Rust 单端口根级标记也会在扩展为多端口前清理并重建。内部统计 API 入站不参与端口自动发现和计费。

预设页的“独立出口归属”展示已保存版本的规划及失败原因，不代表节点部署或采样已成功。Agent 仍根据 sing-box 构建能力选择 API 或标记路径；标记配置无法安全应用时部署失败，不以旧监听口径宣称成功。上线前应升级 Agent，并在部署成功后检查流量页实际统计来源。公网出口 IP 不因独立 tag 或标记而改变。

高级字段修改也会重建已有托管出口映射，无法保持安全归属时不保存。预设、字段、手动配置及档案页面提交配置任务时携带期望版本，数据库在锁定配置后核对版本；若保存后被其他操作更新，拒绝提交任务，不部署另一份内容。保存和任务提交仍是两个步骤，任务提交失败不撤销已保存的版本。

Xray / sing-box 手动配置页提供“单文件迁移到多文件”按钮：确认当前编辑内容后保存一个数据库版本，再提交常规部署任务，校验、生成源码包、备份并重启；失败沿用原有回滚流程。取消确认不写入。必须升级到声明 `config-files-v1` 的 Agent；旧 Agent 按钮禁用并提示升级。外部系统服务的只读导入页、只读用户、Mihomo 和 SS Rust 不显示该迁移按钮。迁移不会改用内核原生目录合并启动方式，运行入口仍是固定路径的合并配置。

Agent 在校验通过后，以提交内容的 SHA-256 为键，使用 0600 私有文件保留输入版本与编译输出的对应关系。同一保存版本再次部署时无需把旧副本与新磁盘副本误判为冲突；编译器仍重新检查输出与当前内核能力。该映射和源码包均属于节点恢复数据，应与 `/etc/qagent` 一起备份。

修改原始入站、出口或路由后，Agent 会对照当前磁盘配置校验未修改的自动生成项，再重新生成对应副本。`qch-trf-` 命名空间的自动副本不应单独修改；无法验证的修改会拒绝校验与部署，不再以警告形式部署旧副本。原生统计使用的目标端口 10085、10086 会在用户路由之前统一拦截（包括域名目标），因此也不能通过这些代理访问远端同端口服务；Agent 直接访问本机 API 不受影响。

Xray / sing-box 手动配置页支持 `00-common.json`、`inbounds/0000.json`、`outbounds/0000.json` 等独立文件切换与只读合并预览。文件编辑合并后作为一个加密配置版本及修订保存在 PostgreSQL；带版本锁，不能部分写入或跨版本混合。Agent 部署时生成内容寻址的 `sources-<sha256>/` 源码目录；内核仍启动经过验证的固定路径合并配置，而非依赖不同内核的目录合并顺序。源码包为不可变版本，先写完再原子替换运行配置，失败回滚不会混合文件。历史源码包保留在节点用于恢复，不自动删除。Mihomo / SS Rust 保持单文件。

```sh
QCH_TEST_DATABASE_URL='postgres://postgres:password@127.0.0.1:5432/postgres?sslmode=disable' go test ./internal/store ./internal/api
go test -race ./internal/agent ./internal/store -run 'Traffic|NFT'
QCH_TEST_NFTABLES=1 go test ./internal/agent -run '^TestTrafficNFTablesNetworkNamespace$' -v
QCH_TEST_NFTABLES=1 go test ./internal/agent -run '^TestMarkedTrafficNetworkNamespace$' -v
```

最后一项需要 `nft`、`ip`、`unshare` 和创建网络命名空间的权限；仅在新建隔离命名空间中发包、安装规则，绝不修改宿主机规则。测试验证 IPv4/IPv6 UDP 的实际字节数、TCP 双向传输、规则刷新后累计保留，以及超额丢包不计费。

真实内核端到端测试使用本地测试二进制，所有监听及 nftables 操作都在独立网络命名空间中：

```sh
QCH_TEST_NATIVE_TRAFFIC=1 \
QCH_TEST_XRAY_BIN=/absolute/path/xray \
QCH_TEST_SINGBOX_BIN=/absolute/path/sing-box-with-v2ray-api \
QCH_TEST_MIHOMO_BIN=/absolute/path/mihomo \
QCH_TEST_SSRUST_DIR=/absolute/path/shadowsocks-rust-binaries \
go test ./internal/agent -run '^TestNativeTrafficCores$' -count=3 -v
```

SS Rust 目录需要同时包含 `ssserver` 与 `sslocal`。使用官方无 Stats API 的 sing-box 时设置 `QCH_TEST_SINGBOX_MARKS=1` 并选择 `-run '^TestNativeTrafficCores$/sing-box$'`。测试通过两个入口发送不同大小 TCP 内容，再通过 SOCKS5 UDP 转发，检查四方向计数和端口隔离；原生 API 重复读取不得重置计数器。
