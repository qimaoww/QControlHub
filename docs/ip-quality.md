# IP 质量检测

“IP 质量”页使用 [xykt/IPQuality](https://github.com/xykt/IPQuality) 检查
Agent 所在环境的出口 IP，保存真实的 IPv4 / IPv6 报告和任务状态。检测通过现有
签名 WSS 任务通道执行，不在控制面运行，也不是针对每个代理入站的出口检测。
页面读取失败时显示错误，不生成演示数据。

## 启用前准备

1. 备份 PostgreSQL，更新控制面、Web 和需要检测的 Linux Agent。
   新 Agent 心跳声明 `ip-quality-v2`；旧 Agent 不会领取这个任务。
2. 节点至少要有 Bash 4+ 与 `curl`：`curl` 用于取回上游脚本。其余探针依赖
   （`jq`、`bc`、`nc`、`dig`、`ip` 等）缺失时，上游一行命令会用节点的包管理器
   自动安装；Agent 传 `-y` 使其非交互执行。以非 root 身份运行且无免密 `sudo`
   时安装会失败，请先手动准备。
3. 以节点所有者或有权管理该节点的管理员登录。读取需要 `agents.read`，
   手动检测和修改每日计划同时需要 `agents.manage` 与 `tasks.execute`。
   接受共享并不授予主机检测权限。
4. 打开“IP 质量”，确认节点在线后点击“立即检测”，阅读第三方访问提示。
   节点通常需要数分钟；页面关闭不会取消已经提交的任务。

Debian / Ubuntu 的依赖安装示例：

```sh
sudo apt-get update
sudo apt-get install --no-install-recommends bash ca-certificates curl jq bc netcat-openbsd dnsutils iproute2 coreutils grep
```

Alpine 的依赖安装示例（以 root 执行）：

```sh
apk add bash ca-certificates curl jq bc netcat-openbsd bind-tools iproute2 coreutils grep
```

脚本获取失败、依赖安装失败、注入点不匹配或没有有效 JSON 报告时，任务明确失败；
修复网络或依赖后可重新检测。不要为使单项探测通过而放宽 Agent 服务权限。

## 每日计划与日期

- 每日检测默认关闭，须逐节点显式开启。启用后在下一个可用维护周期
  （通常每分钟扫描一次）提交首次检测，之后按实际提交时间间隔 **24 小时**；
  不是当地午夜的 cron，也不因夏令时调整为固定钟点。
- 离线或不再声明该功能的节点等待重连/升级，错过多日只补一次，不批量补跑。
  在线判断沿用节点所有者的离线阈值，不使用当前管理员的设置。
- 同一账号、同一节点的未完成检测会复用；其他账号已有未完成检测时拒绝重复创建。
  关闭每日计划不取消已经提交的任务；尚未领取的任务可在任务页取消。
- 每个节点只有一个计划，记录最后设置它的账号。每次提交前重新核验账号当前身份、
  权限和节点管理权，授权失效时关闭计划。永久删除账号会删除其计划，不自动转交。
  旧版低权限兼容令牌没有可持久核验的授权，因此不能设置每日计划；管理员令牌可用。
  计划状态按节点管理权可见，节点所有者能够看到并关闭管理员开启的计划；
  这不会授予读取其他账号检测报告的权限，共享接收者也不能查看或修改计划。
- 日期选择使用浏览器的 IANA 时区，标签会显示该时区。按**任务提交日**归档，
  每个节点展示该日最新一次尝试，包括失败或仍在执行的尝试；跨午夜完成的任务仍
  属于提交日。具体时间的显示沿用账号的时间显示设置。
- 今天展示自有节点并提供立即检测和每日计划设置；历史日期仅展示该日有记录的节点，
  不提供检测或计划修改按钮。通过“回到今天”可恢复操作；确认期间切换日期或跨午夜后，
  原来的确认不会继续提交。
- 左侧“选择节点”侧栏按节点单选，与内核日志、端口流量等页面一致：选中哪个节点，
  主区只显示该节点的报告与操作，默认选中列表中的第一个节点。侧栏和主区使用同一份
  当日节点列表，因此历史日期不会列出当天没有记录的节点，也不会出现高亮节点与显示
  内容不一致的情况。切换节点复用已读取的快照，不重新请求接口；切换日期后仍可见的
  选中节点会保留，选中节点不再可见时回到列表中的第一个节点。
- 页面可见时每 5 秒读取状态，不会因读取而执行检测。切换日期、账号或离开页面后，
  旧请求不能覆盖新页面；读取异常时暂停操作并标记同日的上次成功快照。

## 如何理解结果

报告保留上游 `Head`、`Info`、`Type`、`Score`、`Factor`、`Media`、
`Mail` 的数据源名称和原始值，并可展开查看 JSON：

- 不同数据库的风险分数不是统一尺度，不合成为一个“质量总分”。
  `null`、缺失或不可用显示为未知，不等于零风险；来源之间可能相互矛盾。
- 媒体和 AI 可访问性只代表本次探测，不保证账号登录、付费内容或后续访问。
- 邮件结果受防火墙、运营商出站限制、NAT、源端口绑定以及 Agent 运行权限影响。
  单项失败不自动证明 IP 被封禁。
- DNS 黑名单是上游黑名单查询，不是 DNS 泄漏或 DNS 可用性测试。
  当前上游脚本只查询 IPv4；IPv6 此项显示“未检测”。上游 IPv6 原始 JSON
  可能沿用 IPv4 黑名单计数，因此保留原文但不把这些数字显示为 IPv6 检测结论。
  本集成**不检测延迟、丢包率、DNS / WebRTC 泄漏**，不会显示虚构的正常状态。
- 成功意味着得到一至两个结构有效、地址族不重复的报告，不意味着所有供应商都可用。
  上游在仅有 IPv4 时可能最终退出为 1；本集成以有效报告为准，超时或不完整 JSON
  不视为成功。

## 执行、隐私与上游来源

IPQuality 由上游按 [AGPL-3.0](https://github.com/xykt/IPQuality/blob/main/LICENSE)
发布。本集成保留来源署名，通过独立进程及 JSON 文件交互；仓库不打包上游脚本。
Agent 仅在收到检测任务时运行上游官方一行命令
`bash <(curl -Ls https://IP.Check.Place)`（302 到 `xykt/IPQuality` 的 `main`
分支 `ip.sh`）。本集成不固定修订、不校验 SHA-256，DNS 黑名单、国家代码等辅助
文件也随上游 `main` 更新；脚本内容由上游控制。

固定参数为 `-y -p -f -o <私有报告路径>`：非交互接受上游安装缺失依赖，
以**隐私模式**运行——不向 `upload.check.place` 上传报告、不生成上游链接——并保存
完整 IP 与机器可读 JSON（保留上游默认语言，使 JSON 中的机房/解锁/原生等标签与终端一致），
并保留上游打印的报告原文供面板出图。不接受调用者传入脚本 URL、路径、接口、代理地址或额外
shell 参数。

**面板直接渲染上游打印的报告原文**（[Agent 实现](../internal/agent/ip_quality_linux.go)、
[渲染实现](../internal/api/ip_quality_render.go)）：不下载上游 SVG、不要求报告链接。
Agent 把脚本打印的每个地址族的报告文本（含 ANSI 颜色码）随结果回传，面板只把
SGR 颜色码映射成调色板后生成 SVG，存入面板数据库并以图片内嵌。因此存档图就是
终端里看到的那份输出，而不是从 JSON 重排的近似结果，上游改版也不会让图片漂移；
JSON 仍按结构化数据保存，用于历史与权限过滤。检测不再依赖上游上传端点的可用性。

出图按**终端字符网格**定位：全角字符占 2 格、零宽字符占 0 格，每段文本用
`textLength` + `lengthAdjust="spacingAndGlyphs"` 固定到自己的格宽，因此列对齐只取决于
上游打印的字符位置，不受浏览器所选等宽字体的字宽影响（等宽字体的 ASCII 步进通常
不是整格，直接按字体步进绘制会让长行逐渐左移、与下方徽章行错列）。加粗、下划线和
背景色块同样按 SGR 还原。斜体只应用于不含全角字符的片段：浏览器没有真正的全角斜体
字形，会合成倾斜，把上游用斜体标注的数据库名、风险等级和页脚里的中文拉歪，而终端
显示的是正体；拉丁文片段仍保留上游要求的斜体。

检测仍会发起第三方网络请求，联系上游及其 IP 数据库、媒体/AI、邮件、DNS 和统计
服务，对方可观察节点出口 IP；隐私模式只关闭报告上传，不减少这些探测。脚本不再
经过固定修订与摘要校验，节点执行的是上游 `main` 上的当前内容；上游各探针也各自
使用自己的 TLS 选项。请仅在获授权、允许此类出站访问的节点启用。

脚本继承现有 Agent 身份及其 systemd/OpenRC 隔离边界，通常仍是高权限身份，
不是不可信脚本沙箱。本功能不增加 capabilities、不更改服务单元、不绕过系统限制。
子进程只接收最小环境，不继承面板密钥、代理环境或 `BASH_ENV`；临时目录私有，
报告只接受不超过 128 KiB 的非符号链接普通文件；该限制在读取报告时检查，
不对包管理器的索引或软件包文件施加进程级文件大小限制。检测最多运行 10 分钟，超时终止整个
进程组；任务租约至少 12 分钟，为结果传输留出时间。它占用节点的既有串行任务通道，
可能延后同一节点的部署或运维任务。

每次结构化结果上限 128 KiB，普通任务列表只含状态及“报告已保存”。
报告原文每个地址族最多 32 KiB，采集缓冲区为两份报告及额外的换行等输出预留空间。
输出被截断、单份报告超限或原文与 JSON 报告份数不匹配时，检测明确失败，不保存残缺存档。
Agent 的报告仅在临时工作目录与有界内存重传缓存中存在，不写入凭据文件；
临时目录在任务结束时清除。同进程断线可重传，Agent 重启后尚未确认的任务可能重新检测。

面板把 Agent 回传的报告原文逐份渲染成 SVG：每份最多 2 MiB，且必须是完整的单一 SVG
文档，最多 IPv4 / IPv6 各一份。渲染或入库失败会将任务记为失败并确认，不会显示
“已存档”；数据库故障仍允许 Agent 重传。SVG 原文、SHA-256 和渲染时间与结构化
报告在同一事务写入**面板数据库**，不会生成面板磁盘文件、对象存储副本或 Agent
归档。旧 JSON 历史仍可读，不伪造 SVG 存档。

前端通过面板鉴权接口把 SVG 作为图片直接嵌入页面，IPv4 / IPv6 分开展示；支持放大及下载。
不把报告插入 DOM 或 iframe，不让浏览器请求上游链接。响应使用 `no-store`、
`nosniff` 和禁止脚本/外链的 CSP；历史接口仅返回元数据，不反复传输 SVG 字节。
面板在隐私模式下不生成也不保存上游链接，QControlHub 的持久副本只在数据库中。

数据库 JSON 和 SVG 报告跟随任务所有者的 `task_retention_days` 清理；
设置为 `0` 时不自动过期。完整 IP 和原始结果未单独加密，须保护数据库及备份。
报告按任务账号隔离，计划状态按节点管理权可见，两者均遵守
管理员隐藏规则。结构有效但无法入库的报告会将任务记为失败并正常确认；
真正的数据库故障仍保留结果重传机会。

## 升级与回滚

本功能将数据库升级到 **schema 65**，添加结构化报告、SVG 归档、计划表及任务约束，不自动开启计划，
不回填历史检测。生产升级前须准备并验证与旧版本匹配的数据库备份。

停止使用时先关闭每日计划，视情况取消尚未领取的任务；当前版本可继续运行而不发起
新的检测。旧二进制会拒绝比自身更新的 schema，因此二进制回滚必须配合恢复升级前
的数据库备份，并统一控制面版本。不能只降低迁移版本号或直接把旧镜像指向新数据库。

常规自动化测试使用本地脚本、报告夹具、真实 PostgreSQL 和签名 WebSocket，
不会运行第三方全网检测。上线验收时应由节点管理员单独发起一次真实检测，
确认当地依赖、网络策略和报告可用性后再开启每日计划。
