# Agent 升级与恢复边界

本页覆盖 Agent 二进制升级、安装资源、四种托管内核前置条件，以及 SS Rust / OU-SB 的受保护资源导入。资源准备和升级预检不会停止原内核或覆盖其运行配置，不增加 CN 域名规则。

## 升级链路

1. 通过已签名 Agent 请求下载候选程序，强制核对 SHA-256、大小与完整响应。空文件、截断、缺失/不匹配摘要、HTTP 错误及取消都会清理临时下载。
2. 检查 ELF 类型及本机架构，在原进程的权限限制下实际运行候选程序的 `upgrade-preflight`。它验证构建版本、准备自身资源包，不注册节点、不读取业务配置、不启动服务。没有预检协议的旧程序不会被在线降级执行；需要明确的人工回退流程。
3. 保存按原程序摘要命名的 `.previous-<sha256>` 备份，再原子替换并同步目录。准备失败保持旧程序不变；结果持久化失败或 `exec` 失败会尝试恢复校验通过的备份，不覆盖第三方后来修改的文件。
4. 等待结果确认后重启进程。确认丢失后建立新的认证连接也会触发待完成重启，不会永久停留在“新文件、旧进程”。跨连接的内核任务串行执行；待重启时拒绝新的变更任务。

旧版 Agent 第一次升级仍由旧二进制执行，无法追溯增加它尚不具备的下载预检。升级到本版后，后续在线升级具备上述检查。本版自身的内核操作仍会按需准备自身资源，因此首次跨版本升级不需要第二次升级或手动修补缓存。

## 测试覆盖

| 路径 | 已验证行为 |
| --- | --- |
| systemd / OpenRC 候选程序 | 实际编译并运行 QAgent 的预检、提交及回退 |
| 错架构 / 错版本 / 非 ELF / 无预检协议 | 拒绝替换原程序 |
| 下载异常 / 取消 / 文件被改写 | 拒绝、清理临时文件、保留原程序 |
| 备份或目标被第三方修改 | 拒绝回退覆盖 |
| 升级确认丢失 / 重复任务 | 保留重启意图和同任务结果，新任务等待升级结束 |
| 四种内核的半安装状态 | 单独检查配置、目录及 SS Rust ACL；只补缺失文件，拒绝符号链接等不安全路径 |
| 活动的 OpenRC 托管服务 | 可读取验证状态，更新不再因“必须 inactive”被提前拒绝 |
| SS Rust ACL / OU-SB 证书 | 使用 `/etc/qagent/<内核>/`，适配旧 Agent 可写目录 |
| 只读根文件系统 | `make upgrade-sandbox-test` 在临时容器中仅开放旧 Agent 写范围、只授予 CAP_CHOWN，实际执行资源释放及程序提交/回退 |

CI 将只读容器回归作为三个镜像构建的前置条件；Alpine 也运行升级预检回归。单元测试中的服务控制使用模拟命令，不等于任意发行版的完整 systemd/OpenRC 实机认证。

## 恢复与限制

安装中断后不应删除现有服务或配置。更新控制面和 Agent，确认原服务仍运行后，重新读取配置快照并提交新的导入任务。已经成功导入的历史资源不会被自动移动或删除；它们仍由已保存配置引用。

候选预检不是完整业务健康检查。任务结果描述的是程序替换和重连过程；升级后应确认节点重新在线并报告目标版本。若新程序在完整启动期间因主机配置、内核安全策略或网络问题退出，可使用保留的摘要备份进行人工回退。权限被管理员收紧到连既有 Agent 私有目录都不可写时，任务应失败，不自动放宽服务权限。

程序备份、历史资源包和硬中断留下的未发布临时目录不会被无限制自动清理；确认没有运行进程或配置引用后再做维护清理。
