# 使用指南

## 节点与配置

1. 在节点管理中添加 Agent，安装需要的内核。系统设置控制新节点的默认内核能力，节点设置可独立调整。
2. 在配置页选择节点、内核和配置文件，通过“增加入站”使用预设，或直接编辑源码。Xray、sing-box 将入站与独立出口放在同一文件，可查看公共配置及合并预览；Mihomo、Shadowsocks Rust 使用单文件。
3. 保存草稿、校验和部署是不同操作。保存不会改变运行服务；“保存并部署”提交固定配置版本的任务，任务完成后在节点管理核对实际运行状态。共享实例启动使用最后部署版本。
4. 通过任务页查看输出和失败原因。首次增加入站可自动安装缺少的稳定版内核；已有内核保留版本。失败后按提示处理并重试。
5. 在客户端接入页查看参数、复制链接或下载配置。分享值来自实际部署版本；各格式的支持范围见[协议与客户端](protocols.md)。

切换配置前保存未提交的源码。版本冲突时重新读取当前版本并核对草稿。入站、通用项和高级字段的表单操作会同时保存配置并创建相应任务；复杂路由或 DNS 引用需要在源码中联合修改。

节点可自定义显示名称，排序按账号维护并在设备间同步。客户端显示名称按内核与监听端口保存；连接地址和协议栈可在节点设置中统一配置。

## 账号与共享节点

账号通过角色和权限控制资源访问。停用保留数据；永久删除会撤销会话与安装凭据、清理个人数据并将节点、配置和模板移交管理员公共范围。当前登录的数据库账号不能删除或停用；管理员变更需保留可用的管理入口。

节点所有者按用户名邀请用户，设置内核、端口及累计 GiB 额度。接收者接受邀请后，在自己的工作区管理独立实例；不同实例监听端口必须分开分配。

| 操作 | 条件 |
| --- | --- |
| 保存配置草稿 | `agent-config.write` 及对应工作区权限 |
| 校验或部署配置 | `agent-config.write`、`tasks.execute`，以及对应内核、端口和有效共享授权 |
| 查看任务 | `tasks.read` |
| 安装缺少的内核 | `tasks.execute`；共享用户只准备授权内核的稳定版，已有版本直接复用 |
| 查看、启停、重启本人共享实例 | 相应任务权限、已接受且启用的共享、新版 Agent；启动需已有确认部署 |
| 宿主机内核升级、卸载及能力开关 | 节点管理范围及相应权限 |

共享自动准备要求 Agent 支持 `shared-core-instances-v1`、`shared-core-prepare-v1`，自动安装还需 `preset-auto-install-v1`；本人实例启停需要 `shared-core-lifecycle-v1`。旧 Agent 提示升级时，由节点所有者处理。

共享不授予宿主机管理权。额度耗尽时仍可查看状态、读取和停止实例，启动与部署受限。撤销共享或释放端口按停机和流量结算流程处理，历史用量保留。

## 流量与客户端同步

流量页按节点、内核、端口和用户查看用量，可设置周期配额与超额封禁。默认显示当前用户，其他用户范围取决于已有可见权限。

“同步端口”从已确认部署的配置生成候选，草稿和仅校验配置不能添加监控。删除入站并成功部署后，旧监听停止计量，保留历史与累计额度；端口授权需由所有者显式释放。

共享实例同时统计客户端入口与独立出口的网络收发，包含协议和网络开销，不等于应用文件大小。批量清零、删除监控、设置或取消个人配额按每条记录验证权限，失败项可重试。

Sub-Store 连接和同步组按账号独立，可选择 URL 或 Mihomo 格式，以及增量或完全托管模式。源配置被替换后需重新选择。Komari 集成在系统设置填写地址和 API Key，再到节点设置绑定服务器 UUID。

## 证书与托管 TLS

证书中心支持导入、自签、ACME 申请、版本、使用授权及实例绑定。签发证书的身份与部署目标的权限分别检查，授权使用证书后仍需目标配置的操作权限。

- **HTTP-01**：域名解析到节点，公网 TCP 80 可达；共享用户还需所有者授予精确域名的 HTTP 认证权限。泛域名使用 DNS-01。
- **托管 Caddy / Nginx**：项目代理将 `/.well-known/acme-challenge/*` 转发至 `127.0.0.1:9080` 并保留 Host。外部代理占用 80 时，由所有者接入该路径，同时核对 A、AAAA 记录。
- **Caddy 来源证书**：升级面板与 Agent 后，已确认的托管部署会自动同步到证书中心；续期由 Caddy 负责，面板同步新版本到仍获授权的绑定实例。删除来源证书会抑制自动重建，手动替换会解除来源关联。
- **私钥与持久化**：启用配置加密密钥后才能同步私钥。备份节点的 `/var/lib/qcontrolhub-tls/caddy/`，保留证书、ACME 账户与续期状态。

托管 Caddy 的 ACME 邮箱在“系统设置 → 证书申请”配置，单个预设可覆盖；修改后需重新部署。签发先使用 Let's Encrypt，有有效邮箱时可回退 ZeroSSL。节点需能访问对应 CA，公网 HTTP-01 路径也须可达。

证书失败先查看任务中的阶段和 CA 错误，再检查 DNS、公网挑战、出站连接或文件权限。网络受限时可选择已有证书的原生 TLS，或自行维护外部反代。具体协议选择见[协议与客户端](protocols.md#tls-方式)。

## 日志与 IPQuality

内核日志可按节点、实例、内核、级别及文本筛选。systemd 从 journal namespace 采集，OpenRC 从 `supervise-daemon` 日志文件采集；系统设置可控制最低保存级别或停止保存新日志。

IPQuality 默认显示最近一次成功报告及检测时间，重新检测期间保留原报告。历史日历只显示有记录的日期；每日计划默认关闭。检测访问第三方服务，缺失结果显示未知；依赖准备及本地诊断见[部署与维护](deployment.md#常见维护问题)。
