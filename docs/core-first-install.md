# 普通用户首次安装内核

## 复现和根因

基线：`main` 的 `1786489a`。使用数据库创建的普通用户，通过密码登录取得会话 Cookie 和 CSRF token，再调用生产 API；没有用兼容 operator token 代替普通用户。

| 操作 | 基线结果 | 修复后 |
| --- | --- | --- |
| 所有者手动安装，具有 `tasks.execute` | 201，已经允许 | 保持允许，补齐进度、失败重试和结果刷新 |
| 接受共享的用户安装宿主机内核 | 403 | 保持 403，提示所有者入口和实例初始化路径 |
| 接受共享的用户增加入站，`install_if_missing: true` | 403 | 在分享授权范围内准备独立实例并继续校验或部署 |

共享首次使用有三处一致性问题：前端 `canAutoInstall` 只允许管理员或 `can_manage`；数据库任务创建把所有 `InstallIfMissing` 都当作宿主机管理；Agent 的任务校验和执行器也拒绝携带共享身份的自动安装。不能只解禁按钮，也不能把宿主机安装权限授予全部共享用户。

`createPermissionChecker`、登录会话和数据库的现有账号权限模型一致。更新权限会使旧会话失效；验收权限组合时需要重新登录。本次保留该行为，也不增加“普通用户”角色的隐含权限。项目没有独立的“委托宿主机管理员”关系：`agents.manage` 本身不会将共享接收者变成节点所有者。

## 权限条件

| 操作 | 账号权限 | 节点或实例范围 |
| --- | --- | --- |
| 手动安装或切换宿主机版本 | `tasks.execute` | 所有者、管理员或现有兼容管理身份 |
| 查看安装任务状态、错误和执行记录 | `tasks.read` | 仍按任务所属用户和节点过滤 |
| 增加入站并自动准备、校验或部署 | `agent-config.write` + `tasks.execute` | 自有节点，或已接受且启用的分享所授权的内核、端口和流量范围 |
| 开关内核能力 | `agents.manage` | 仍需宿主机管理范围 |

没有 `tasks.read` 时可以提交已获准的安装任务，界面说明无法读取任务结果，可刷新节点状态。仅有任务查看权限不能安装。无执行权限、能力未启用、内核不受支持、节点离线、旧 Agent 和正在安装分别给出原因。

## 共享实例准备

受控准备要求 Agent 同时声明 `preset-auto-install-v1`、`shared-core-instances-v1` 和新增的 `shared-core-prepare-v1`，以及现有共享和独立出口能力。新能力只在使用标准 QAgent 服务路径时上报。旧 Agent 或自定义执行路径需要所有者先升级或检查配置，不能回退到宿主机安装。

任务保留 `owner_id`、`shared_traffic_id`、`shared_instance`、`config_id`、`config_version` 和不可变配置快照。准备和原始操作属于同一个任务。缺少二进制时复用现有稳定版选择、可信发布源、SHA-256 校验、归档检查和原子发布流程；已有可执行文件直接复用，保留版本。已有文件不可执行时失败并要求所有者处理。

共享准备只创建受保护的托管目录、缺少的内核二进制及受认可的实例服务模板。校验不启动服务、不写入已部署配置；部署只操作对应分享实例。所有者的配置、主服务及启用状态不被改写。二进制属于现有共享实例模型中的节点级只读资源，实例配置、服务名称、端口分配和累计配额仍独立。

现有节点事务锁保证每个 Agent 同时只执行一个任务；等价的待执行任务复用，失败后可以重试。任务领取、断线恢复和结果确认重新检查持久权限；排队后撤销执行权限、停用用户或取消分享会阻止继续领取。运行中失去授权的任务被标记失败，不会把未知的远端执行结果报告为成功。Agent 降级丢失准备能力同样阻止恢复。

## 验证

需要 PostgreSQL 测试库；测试自行创建隔离数据库，不能指向生产库。

```sh
export QCH_TEST_DATABASE_URL='postgresql://postgres:password@127.0.0.1:5432/qcontrolhub?sslmode=disable'
make test
make non-browser-checks
make browser-checks
make upgrade-sandbox-test
```

- API：四种内核的所有者手动安装、管理员回归、所有者自动校验、共享自动校验和原版本部署；普通用户真实密码会话与独立执行、查看、管理权限组合。
- 数据库：两个接收者的配置快照、端口和实例身份隔离，任务串行和重复复用；排队及运行恢复时的权限撤销、分享取消、账号停用和能力降级。
- Agent：Mihomo、Xray、sing-box、Shadowsocks Rust 的稳定版真实下载器和归档提取，正确或损坏的 SHA-256、失败不发布二进制、不触碰主服务；只读 Docker 沙箱内的完整首次准备与重复校验路径。
- 浏览器：1440px 桌面及 390px 移动端，真实密码登录、Cookie 和 CSRF；所有者安装失败、完整长错误、重试、版本刷新；所有者和共享用户增加入站自动部署；现有完整浏览器矩阵。

测试边界：API 和浏览器使用确定性的远端 Agent 完成器；下载使用带真实摘要的发布夹具。Docker 沙箱运行真实执行器和文件操作，systemd 管理命令及内核校验程序使用测试进程。没有将这些结果表述为公网下载或真实远端 systemd 服务启动验收；服务启动失败、回滚及运行权限由项目现有执行器回归测试覆盖。

## 发布与回滚

先更新控制面，再由所有者在节点设置升级 Agent。自有节点手动安装不依赖新增特性；共享自动准备需要上述新特性完成握手。无需数据库迁移。

回滚控制面和 Agent 到此前版本即可恢复原有授权限制。回滚前等待或取消未完成的准备任务；原版本不能继续新的共享准备任务。不要删除已保存的用户配置、分享分配、实例目录或二进制，避免影响已运行实例。
