Core logs follow-up: backend measurements (2026-10-11)

Environment: Linux 6.12.107+deb13-amd64, amd64, Intel i5-12500; Go 1.25.12;
PostgreSQL 18.6 on Alpine (postgres:18-alpine), local Docker published TCP.
This is real Store + PostgreSQL + API permission/gzip middleware using an
in-process httptest HTTP transport; synthetic log data, not production Agents.
CPU is a shared development host; results are comparative observations, not
latency guarantees. No test assertions use timing thresholds.

API fixture: 3 nodes x 4 engines x 2000 rows, read one node's 8000-row window.
Messages: 160 or 4096 bytes, MD5-varied prefix plus repetitive diagnostic text.
The 4096-byte fixture is compressible; see the separate existing incompressible
B-tree index size limitation in the follow-up validation report.
VACUUM ANALYZE and one warm fetch precede timed batches, so these are warm
backend reads, not a cold-disk or real-network browser benchmark.
Each result below is one 30-iteration batch; 3 batches per scenario.
body-bytes/op is gzip response-body bytes, excludes HTTP headers.

The SAME internal/api/core_logs_bench_test.go was copied to a detached worktree
at df1ad925aa270a146b2ad342143546d8ff74c1ea; baseline product code was unchanged.
Baseline command (only unconditional is compatible with the old API):
  QCH_TEST_DATABASE_URL='<isolated postgres URL>' go test ./internal/api -run '^$' -bench 'BenchmarkCoreLogRefresh/.*/unconditional' -benchtime=30x -count=3
Follow-up command:
  QCH_TEST_DATABASE_URL='<isolated postgres URL>' go test ./internal/api -run '^$' -bench 'BenchmarkCoreLogRefresh/.*/(modified|unchanged)$' -benchtime=30x -count=3

Query fixture: existing TestCoreLogWindowMeasurements, 4 nodes x 40000 rows,
950-byte messages over seven receive days, VACUUM ANALYZE, production SQL.
Rows below are single diagnostic observations; they are not medians. The first
node reads brought 56/112/112 blocks into PostgreSQL shared buffers, while
subsequent aggregate reads were shared-buffer hits; OS caches were not reset.
No production SQL/schema changes were made in this follow-up.
  QCH_TEST_DATABASE_URL='<isolated postgres URL>' QCH_CORE_LOG_MEASURE=1 go test ./internal/store -run '^TestCoreLogWindowMeasurements$' -count=1 -v

Upload fixture: real StoreCoreLogs 32-row batch, local PostgreSQL connection.
RemoteDatabase injects 20 ms per protocol write, not a measured production RTT.
  QCH_TEST_DATABASE_URL='<isolated postgres URL>' go test ./internal/store -run '^$' -bench '^Benchmark(Local|Remote)Database/logs32$' -benchtime=15x -count=1
