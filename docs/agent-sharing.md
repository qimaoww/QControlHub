# 用户与 Agent 分配

## 操作

1. 管理员打开“用户”，创建普通账号并授予所需操作权限。普通账号的资源始终独立，不能关闭隔离。
2. 用户有 `enrollment.manage` 时可自行添加 Agent。安装凭据与节点归创建账号所有；不同账号可使用相同节点名称。自有节点的主机操作仍需对应能力。
3. 节点所有者打开“节点设置 → 具体节点 → Agent → 管理共享”，填写接收者的准确用户名、代理监听端口和总额度，并勾选允许使用的内核。至少选择一个该 Agent 支持的内核。额度单位为 GiB（1024³ 字节），`0` 不限量；取消“启用”撤销共享，不清零账本。
4. 管理员在“用户”中选中账号，点击“共享节点 → 分配节点”，在弹窗内选择节点、内核、端口，以及“不限量”或“设置总额度”，点击“发送邀请”直接保存。列表只展示已保存的分配；逐项“编辑”并保存修改，无需再次全局保存。取消或关闭弹窗不保存。自有节点单独列出，不重复分配。撤销使用独立的“撤销”按钮并确认；修改已撤销分配不会恢复共享，需另行“重新邀请”。
5. 接收者打开“共享 → 共享与额度 → 查看邀请”，在独立弹窗内核对所有者、Agent、内核、端口和额度，选择“接受”或“拒绝”；手机显示为整页弹层。关闭弹窗不等于拒绝。接受前没有节点访问或任务权限。发送方能看到待接受、已接受、已拒绝状态；拒绝后须显式“重新邀请”（所有者在管理共享中保存，管理员在分配弹窗中发送），普通编辑不会重新发送。
6. 接受后，借用者在自己的节点工作区或配置档案中保存配置，使用获分配的内核及固定端口部署；共享节点带“共享”标记，只显示获分配内核和配置入口。“共享与额度”显示累计用量，也可“退出共享”。追加额度时填写新的**总额度**，不是本次增加量。已接受共享的端口/额度调整不重复邀请；增加内核或撤销后重新启用必须再次接受。仅减少内核保留接受状态，但立即撤销对应内核的访问及旧任务，Agent 收到策略后阻断该内核的共享端口。

普通用户不能选择他人的配置、历史版本、模板、任务或同步组。每用户每节点每内核有一个当前工作区，可以另存多份配置档案。

面板设置、Sub-Store 后端连接及同步组、Komari 凭据、Webhook、审计和浏览器节点/日志偏好均按账号保存，不继承管理员的私有设置。运行策略、主机日志采集和指标保留只作用于自有 Agent；共享者不能修改宿主机策略。任务失败通知发给任务所属账号。主题作为非敏感外观选项在同一浏览器共用。

客户端显示名称、地址和协议栈绑定自己的实际部署配置及入站；另一账号接管相同端口时不会继承。借用者不能读取安装命令、重装/删除节点、操作主机服务/BBR/Komari、读取主机日志或再次分享节点。

## 运行与端口

每台 Agent 每种内核只运行一份配置，不会为每个面板用户启动独立内核进程。需要同时运行时使用不同内核或独立 Agent。跨用户内核交接须由节点所有者或管理员先停止服务并完成最终结算；失败或失联的部署按状态不明处理。节点所有者也不能通过读取/导入宿主机配置获得借用者的完整配置。

共享配置要求同时声明 `shared-traffic-v1`、`shared-engines-v1`、`independent-egress-v1` 的新版 Agent，并使用可完整计费的固定端口服务端监听器。不支持 TUN、动态端口、可修改路由的管理 API、插件监听和额外 DNS 监听；Xray / sing-box 的内置统计 API 只允许固定回环地址。新用户填写任意草稿不会创建主机防火墙规则。

所有账号的配置校验与部署均强制检查独立出口：每个代理入站必须能生成可归属的独立出站标签或 socket mark，不能复用无法区分的出口、转交未知路由或通过管理 API 动态改写路由。检查同时发生在任务提交、领取/恢复及 Agent 执行阶段；失败不会改写运行配置或降级为原样部署。自有节点可提交显式空监听列表删除最后一个入站，但须没有隐藏入口，并通过真实内核的格式校验；共享部署仍须至少一个获分配的固定监听端口，停用共享可选择“退出共享”或由所有者停机。保存草稿本身不表示校验通过。

独立出口是配置路由及计量归属，不代表不同公网 IP、独立进程或独立网络命名空间。已运行的旧配置不会仅因控制面升级而被自动停机或保证完成转换；仅所有者可用的 `import-existing` 保留精确迁移旧服务的流程，不代替独立出口校验，后续校验或部署须满足上述要求。

端口留空表示“未分配”，不能校验或部署任何监听端口；单独填写 `0` 表示“无限制”，不限制可选端口范围。`0` 不能与端口或范围混用，也不会成为真实监听端口。无限制不绕过内核授权、累计流量额度、系统保留端口或其他用户的端口占用。

“用户分配”和“管理共享”也支持指定单个端口、范围及混合填写，例如 `21000-21100, 22000`（共 102 个，包含范围首尾）。逗号、中文逗号或空格可分隔多项；范围不能倒序、重叠或包含保留端口，展开后最多 256 个。保存后连续端口按范围显示。

指定端口由节点所有者或管理员预留；无限制模式在部署时才为实际固定监听端口预留并绑定共享计费，保存草稿、仅校验或发送邀请不会新建计费策略。两种模式都不允许占用他人已预留、已部署或正在部署的端口；其他用户的部署状态不明时，须先停止对应内核再分配新端口，不影响撤销已有授权。同一 Agent 最多 256 个预留共享/监控端口，10085、10086 保留。只使用代理端口，不要使用 SSH 等宿主服务端口；面板无法发现所有未托管的宿主服务。

邀请待接受、拒绝、退出或撤销仍保留已有端口和账本。切换到无限制也保留此前预留端口；改回指定范围或留空时才释放不再授权的端口。已绑定计费的端口须在内核成功停止、最终流量入账且没有待处理任务后释放。缩小端口权限会作废旧的校验任务，不改变累计用量。

节点所有者或管理员可停止共享内核。恢复运行使用重新部署，不能直接启动未经重新绑定计费的旧文件。关闭内核能力再开启时，只恢复管理能力，由后续部署启动服务。

## 计费与恢复

- 同一用户在同一 Agent 上的全部共享端口共用累计额度，只计监听端口接收 + 发送的网络字节，不重复计算代理出口，也不依赖用户可重置的内核 API。
- 不按月清零；更换配置、内核或 Agent 重启、撤销后恢复、释放端口均不清零。共享端口不能从普通流量页单独重置、关闭监控或修改配额。
- Agent 把服务端已入账总量与本地未确认增量合并判断；断开控制面后仍执行最后收到的限额。远端额度调整、退出、撤销或停用须待 Agent 在线接收策略后才作用于实际流量，面板访问权限立即生效。撤销或退出会取消未执行任务并作废已派发的旧租约；已在执行的结果可能不明，再次接受不会恢复这些旧任务。
- 计数和策略写入本地受保护检查点。计费后端或持久化不可用时停止相关共享内核；检查点丢失、损坏或早于独立激活记录时停机，等待认证后的策略恢复。首次启用共享时，激活记录写入失败也会停止相关内核。
- 默认约一秒采样，可能少量超额，不是逐包硬限额。同时丢失本地与内核计数时只能恢复服务端已确认用量，不能还原未上报字节。

这是面板权限和监听端口计费隔离，不是 OS 沙箱，也不限制用户配置产生的全部后台流量或主机资源。只能给可信配置操作者使用；不可信租户应使用独立虚拟机/容器及独立 Agent。详见 [安全边界](security.md#多用户配置隔离)。

## API

`POST /api/v1/users` 创建的普通账号始终隔离，旧字段 `agent_isolation` 不再用于关闭隔离。节点所有者通过 `GET /api/v1/agents/{id}/sharing` 获取 `revision`，再以同路径 `PUT` 保存：

```json
{
  "revision": 1,
  "shares": [
    {"username": "bob", "enabled": true, "engines": ["mihomo", "xray"], "limit_bytes": 107374182400, "ports": [21001, 21002]}
  ]
}
```

用户名精确匹配（忽略大小写），不提供用户目录。管理员的用户分配接口 `GET /api/v1/users/{id}/agent-access` 也返回 `revision`，同路径 `PUT` 示例：

```json
{
  "revision": 1,
  "isolated": true,
  "shares": [
    {
      "agent_id": "agt_example",
      "enabled": true,
      "engines": ["mihomo"],
      "limit_bytes": 107374182400,
      "ports": [21001, 21002]
    }
  ]
}
```

两种接口的 `ports` 约定相同：省略或 `[]` 表示未分配，`[0]` 表示无限制，其他值为展开后的整数数组（不接受范围字符串）。`[0, 21001]`、重复端口或保留端口返回 `400`。无限制分配即使已部署并绑定实际端口，读取和再次保存仍使用 `[0]`。

两种保存接口均返回最新分配及修订；并发旧修订返回 `409`，缺少修订返回 `400`。启用共享时 `engines` 必须非空且属于 Agent 支持的内核，可选值为 `mihomo`、`xray`、`sing-box`、`ss-rust`，不能省略来表示“全部”。省略的已有分配会被撤销而非删除，账本及原端口仍保留。`enabled: true` 仅代表发送方启用共享，不代表接收者已经同意。增加内核使已接受分配重新进入 `pending`；减少内核不要求重复确认。对已拒绝的分配可显式传入 `reinvite: true`，重新进入 `pending`；普通保存保留拒绝结果。借用者不能修改自己的分配。

`GET /api/v1/agent-access` 返回当前用户的 `owned_agent_ids` 和共享分配，包含 `id`、`owner_username`、`enabled`、`status`（`pending` / `accepted` / `rejected`）、`invitation_revision`、`engines`、`limit_bytes`、`used_bytes` 和 `ports`；撤销记录仍可见。只有启用、已分配内核且 `status: "accepted"` 的共享授予对应内核的访问权。

接收者通过 `POST /api/v1/agent-access/{share_id}/response` 作出决定，不需要主机管理权限：

```json
{"revision": 1, "decision": "accept"}
```

`revision` 使用该分配的 `invitation_revision`；`decision` 为 `accept` 或 `reject`。`reject` 也可退出已接受的共享。接口返回完整的当前账号分配。只有该接收账号能响应，所有者和管理员不能代为接受/拒绝；Cookie 会话须携带 CSRF 头。缺少修订或决定无效返回 `400`，他人邀请返回 `404`，撤销、已响应或过期修订返回 `409`。响应会更新所有者和管理员编辑修订；额度/端口变更会使旧邀请修订失效，流量采样不会。

Agent 列表的 `can_manage` 区分自有与借用节点，`shared_engines` 表示借用者获分配的内核；借用者看到的 capabilities 和 runtime 也限制在该范围内，不含宿主配置读取信息。未分配内核的工作区、任务、历史、客户端、流量和 Sub-Store 来源同样不可访问。管理员保留全局管理权；节点所有者可把节点设为“不让管理员查看管理”，此时管理员和兼容令牌在常规列表、配置、任务、日志、指标、流量、审计及安装凭据中都看不到它（直接访问返回 `404`），只能在“其他用户节点”目录里只读查看摘要并删除该节点，部署、改配置、启停、共享和修改隐藏状态仍被拒绝，所有者可随时恢复可见。旧版兼容令牌保留原来的节点访问能力，建议迁移到具名账号。

## 升级

先备份 PostgreSQL，再升级全部控制面实例至 schema 60 和 Agent，不与不校验邀请、内核分配或端口模式的旧控制面混跑。v59 → v60 只新增端口权限模式，旧指定端口和空分配保持原义，不自动变为无限制；共享 ID、接受状态、预留端口和累计账本保留。

从尚未支持明确内核授权的旧版本升级时，未明确内核的共享清空内核范围并进入待接受状态（已拒绝保持拒绝），所有者须重新分配内核，接收者确认后才能继续使用。共享 ID、预留端口及累计账本保留；已绑定策略在 Agent 收到更新后阻断，旧敏感排队任务取消、已派发租约作废，旧主机读取快照清除。旧 Agent 不授予共享运行能力；新 WSS 连接在本连接心跳确认特性前不会解除共享端口阻断。

已有普通账号也改为独立范围；旧节点和旧安装凭据归管理员保管，不猜测创建人，需显式邀请并接受后才能被普通用户使用。升级迁移保留实际部署的精确修订、已有累计账本、客户端显示设置和 Sub-Store 远端归属，不采用未部署草稿，也不复制管理员集成凭据。历史失败/失联的配置保持不明状态，不能据此启用计费。回滚需恢复对应版本的数据库备份。
