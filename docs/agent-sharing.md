# 用户与 Agent 分配

## 操作

1. 管理员打开“用户”，创建普通账号并授予所需操作权限。页面默认开启 Agent 隔离。
2. 添加 Agent，填写代理监听端口和总额度后保存。额度单位为 GiB（1024³ 字节），`0` 不限量；勾选表示允许访问，取消勾选表示撤销。
3. 用户在自己的节点工作区或配置档案中保存配置，使用获分配的固定端口部署；“我的额度”显示累计用量。
4. 追加额度时填写新的**总额度**，不是本次增加量。关闭隔离会恢复按权限访问所有节点并停用额度限制，已设额度和累计用量仍保留。

普通用户不能选择他人的配置、历史版本、模板、任务或同步组。每用户每节点每内核有一个当前工作区，可以另存多份配置档案。

## 运行与端口

每台 Agent 每种内核只运行一份配置，不会为每个面板用户启动独立内核进程。需要同时运行时使用不同内核或独立 Agent。涉及隔离用户的内核交接须由管理员先停止服务；失败或失联的部署按状态不明处理。

共享配置要求声明 `shared-traffic-v1` 的新版 Agent，并使用可完整计费的固定端口服务端监听器。不支持 TUN、动态端口、管理 API、插件监听和额外 DNS 监听；Xray / sing-box 的内置统计 API 只允许固定回环地址。新用户填写任意草稿不会创建主机防火墙规则。

端口由管理员预留，同一 Agent 不得分配给两人；最多 256 个共享/监控端口，10085、10086 保留。只分配代理端口，不要使用 SSH 等宿主服务端口。撤销访问仍保留端口和账本；清空端口才释放。已绑定计费的端口须在内核成功停止、最终流量入账且没有待处理任务后释放。

管理员可停止共享内核。恢复运行使用重新部署，不能直接启动未经重新绑定计费的旧文件。关闭内核能力再开启时，只恢复管理能力，由后续部署启动服务。

## 计费与恢复

- 同一用户在同一 Agent 上的全部共享端口共用累计额度，只计监听端口接收 + 发送的网络字节，不重复计算代理出口，也不依赖用户可重置的内核 API。
- 不按月清零；更换配置、内核或 Agent 重启、撤销后恢复、释放端口均不清零。共享端口不能从普通流量页单独重置、关闭监控或修改配额。
- Agent 把服务端已入账总量与本地未确认增量合并判断；断开控制面后仍执行最后收到的限额。远端额度调整、撤销或停用须待 Agent 在线接收策略后才作用于实际流量，面板访问权限立即生效。
- 计数和策略写入本地受保护检查点。计费后端或持久化不可用时停止相关共享内核；检查点丢失、损坏或早于独立激活记录时停机，等待认证后的策略恢复。首次启用共享时，激活记录写入失败也会停止相关内核。
- 默认约一秒采样，可能少量超额，不是逐包硬限额。同时丢失本地与内核计数时只能恢复服务端已确认用量，不能还原未上报字节。

这是面板权限和监听端口计费隔离，不是 OS 沙箱，也不限制用户配置产生的全部后台流量或主机资源。只能给可信配置操作者使用；不可信租户应使用独立虚拟机/容器及独立 Agent。详见 [安全边界](security.md#多用户配置隔离)。

## API

`POST /api/v1/users` 接受 `agent_isolation`；旧调用省略时保持兼容的非隔离模式。管理员通过 `GET /api/v1/users/{id}/agent-access` 获取当前 `revision`，保存必须原样携带：

```json
{
  "revision": 1,
  "isolated": true,
  "shares": [
    {
      "agent_id": "agt_example",
      "enabled": true,
      "limit_bytes": 107374182400,
      "ports": [21001, 21002]
    }
  ]
}
```

`PUT /api/v1/users/{id}/agent-access` 返回最新分配及修订；并发旧修订返回 `409`，缺少修订返回 `400`。省略的已有分配会被撤销而非删除，账本及原端口仍保留。隔离用户不能修改自己的分配。

`GET /api/v1/agent-access` 返回当前用户的分配，包含 `enabled`、`limit_bytes`、`used_bytes` 和 `ports`；撤销记录仍可见。管理员和兼容令牌不受 Agent 隔离限制。

## 升级

先备份 PostgreSQL，再升级控制面至 schema 53 和 Agent。旧用户保持原访问范围，管理员逐个开启隔离。升级迁移使用已部署的精确修订，不采用未部署草稿；历史失败/失联的配置保持不明状态，不能据此启用计费。回滚需恢复对应版本的数据库备份。
