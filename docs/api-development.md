# 新增功能 API 规范

本规范用于 QControlHub 面板、API Key 和 Agent 功能的设计、实现与审查。调用方从当前面板下载 `GET /api/v1/openapi.json`，并用 `GET /api/v1/api-key` 核实自己的有效权限和端点。开发者在注册路由、实现和测试的同一个 PR 中更新契约。机器格式采用 [OpenAPI 3.1](https://spec.openapis.org/oas/v3.1.0.html)。

## 为每个操作填写的契约

| 项目 | 在 PR 中说明的内容 |
| --- | --- |
| 操作与结果 | HTTP 方法、版本化路由、唯一且稳定的 `operationId`、用途、返回的资源或可查询结果。优先扩展已有资源。 |
| 身份与目标 | 支持的认证方式、Key 模式、必需权限及其“全部”或“任一”关系。标明创建者、工作区、稳定 Agent ID、主实例或共享实例、配置和依赖资源的归属。 |
| 输入 | 路径、查询、请求头、媒体类型、正文上限、字段类型和单位。写清必填、默认、枚举、互斥和条件必填，以及省略、`null`、零值和空数组的不同含义。 |
| 副作用 | 说明是否改变当前值、配置版本、档案、任务、部署、绑定或运行服务。每种成功状态码对应一个明确的完成条件。 |
| 并发与重试 | 写出版本字段、版本读取入口和冲突处置。若支持幂等提交，定义关联 ID 的作用域、重复请求的结果、同 ID 不同输入的行为。 |
| 响应与失败 | 声明全部业务成功响应的媒体类型、字段和必要响应头。列出调用方需要分支处理的状态码、稳定错误码、字段和可执行的恢复动作。 |
| 兼容与证据 | 说明已有客户端、旧 Agent 能力、旧数据和历史结果的行为。附正常、受限、冲突或失败场景的脱敏 HTTP 证据。 |

## 权限与数据范围

在服务端分别校验入口权限与目标归属。委托 Key 的有效能力取 Key 模式、显式授权、创建者当前权限及资源授权的交集。可委托的路由在 `internal/api/api_key_policies.go` 声明。只接受 Key 的自查接口、浏览器会话接口、公开接口和 Agent 签名接口分别声明实际的 `security`。

对嵌套引用、批量成员、后台领取、重连、结果查询和恢复操作逐次检查适用范围。稳定 ID 用于寻址。地址、域名、展示名和端口仅作查询线索。遇到不可见成员时只披露安全的占用或阻碍摘要。区分可见结果为空、观测不完整和已确认资源空闲。

凭据使用与凭据读取分别授权。普通编辑优先接受引用或最小变更，由服务端保留已有敏感字段及未知自定义字段。明确替换或清除时定义独立语义。客户端输出按操作选择安全字段，错误、日志、样例和测试失败信息应用相同保护。

## 写入、验证与恢复

| 语义 | 响应和验收 |
| --- | --- |
| 读取或纯预览 | 可以返回阻碍及缺失证据。标明观测时间或后续检查阶段。重复调用前后比对业务持久状态和运行状态。 |
| 保存并验证 | 说明保存的新版本、档案和任务 ID。验证失败时交代已保存的状态。 |
| 保存并部署或提交协调操作 | 分开说明受理、Agent 执行、逐资源验证、版本发布的时点。成功受理异步操作时提供稳定查询标识。新增使用 202 的接口同时返回同源 `Location`。 |
| 回滚或恢复 | 记录原版本、候选版本、各目标的恢复结果、所停步骤及人工处理条件。用原版本和归属保护后来的合法修改。 |

并发写入在事务内检查授权、目标和版本。多成员操作在第一次业务写入前检查整个受影响组。重启后可凭持久状态与节点回执继续核实。每条业务验证结果携带其资源身份和证据，分别定义成功、失败、证据不足。配置已提交、进程存活和业务数据往返是不同的完成条件。

收到 409 后重新读取资源和版本，保留调用方的草稿。写请求超时后先查询原操作。认证限流的 429 带 `Retry-After`，客户端把请求与等待计入总预算。等待预算不足时返回原任务 ID 及必要的等待信息。读取失权、目标失效、用户取消或进入终态时结束轮询。

## 契约源码与发布

1. 在实际路由和处理器定义 HTTP 行为。使用具名 Go 请求及响应类型，使生成器能识别字段。用 `internal/apidoc/semantics.go` 补充 Go 类型表达不了的限制、错误、生命周期和示例。
2. 运行 `go run scripts/generate-api-spec.go` 更新 `internal/api/contract/openapi.json`，再运行 `go run scripts/generate-api-spec.go --check`。为多方法共用处理器分配独立操作标识。检查路径参数、必填字段、响应状态、媒体类型和示例的一致性。
3. 从隔离面板下载 OpenAPI 和管理 Skill ZIP。用发行包里的客户端以测试 Key 查询有效端点、执行示例并核对结果。会改变业务行为的接口还需核对持久状态和运行结果。涉及真实协议时记录客户端、证书校验、业务数据及目标后端。
4. 在 PR 的 Validation 中列出测试角色、执行过的场景和未验证边界。例子用合成身份、测试域名与临时凭据。机器规范与面板说明、Skill 命令和实际路由随同一版本发布。

## 参考实例

TLS 前端迁移的预览返回 `plan_id`、各配置的保存与部署版本、阻碍和待执行的运行时检查。提交时复用同一选择，并提供调用方预先保存的 `task_id`。202 的 `Location` 指向原操作。查询返回的 `result.paths[]` 每行包含 `config_id`、`instance_id`、`engine`、`tag`、`path`、`candidate` 和 `recovery`。读取已确认恢复的操作得到 `rolled_back`，仍需处理的恢复得到 `recovery_incomplete`。示例和字段约束见发行 OpenAPI 的预览、执行和状态查询三个操作。
